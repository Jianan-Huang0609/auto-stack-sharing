03 · The Secret

三条路径，不是一个工具

核心洞察：按确定性给任务分类。不同的问题需要不同的引擎。

路径 1 · n8n / Dify

确定性管道。固定路径，永远运行。cron、webhook、数据同步。

路径 2 · Skill

专家经验注入。一次性高质量输出，最佳实践编码其中。

路径 3 · Agent / CLI

运行时决策。多步推理。"边跑边想。"
问题回答→
能在跑之前画出完整流程图吗？能n8n/Dify
是单次高质量输出？是Skill
需要运行时决策？是Agent
判断法则

能画出流程图 → n8n。需要专家品位 → Skill。需要一步步想 → Agent。

03 · The Secret

Three Paths, Not One Tool

The key insight: sort tasks by determinism. Different problems need different engines.

Path 1 · n8n / Dify

Fixed path, runs forever. Deterministic: cron, webhooks, data sync.

Path 2 · Skill

Expert context injection. Single-shot, high-quality output with encoded best practices.

Path 3 · Agent / CLI

Runtime decisions. Multi-step reasoning. "Figure it out as you go."
QuestionAnswer→
Can you draw the flowchart before running?Yesn8n/Dify
Single-shot, high-quality output?YesSkill
Needs runtime decisions?YesAgent
The rule

If you can draw the flowchart → n8n. If you need expert taste → Skill. If you need to figure it out → Agent.

08 · On-Ramp C

MAE — 我不得不解决的 5 个工程难题

"一个调用 LLM 的脚本" 和 "一个能自己跑好几天的 agent 系统" 之间，差了这五道坎。

#什么坏了解法关键决策
1 状态混乱 — 任务挂了显示 pending，每天早晨手工排查 状态机 — LOADED→RUNNING→REVIEW→DONE，91 行代码强制校验 Dict 不是 DB。显式转换优于隐式约定
2 并发冲突 — cron 重复触发，同一任务并行跑，Airtable 写脏 幂等锁 — claim/release/lease-expiry/sweep，锁存在 Airtable 字段里 零新基建。Airtable 就是分布式锁存储
3 LLM 信任 — LLM 说"done"但代码没写，research 声称完成但无证据 LENS Gate — 机械校验：run_id + log_summary + writeback_ts 必须全部非空 LLM 不能验证 LLM。这个教训来自 CER Evals
4 记忆断裂 — pipeline 第 3 步完全不知道第 1 步做了什么 TaskContext — 每一步输出 append 到 Airtable messages[]，全量注入 prompt 纯文本追加，不搞向量库。简单、可调试、有效
5 人机断连 — 任务跑了几小时，地铁上看不到进度、无法介入 Checkpoint 系统 — review/decision/blocked/notify 节点，微信→Dashboard 操控 飞书推 + Airtable 存 + 微信控
正确的建造顺序

第 1 周：n8n cron + Airtable 队列 + 单次 LLM 调用。人工验证。第 2 周：加状态机 + LENS gate。第 3 周：加锁 + TaskContext。第 4 周：Checkpoint + 多 Agent。不要一开始就建全栈。每加一层，是因为前一层的痛已经真实发生。

08 · On-Ramp C

MAE — 5 Engineering Challenges I Had to Solve

The gap between "a script that calls an LLM" and "an agent system that runs itself for days."

#What BrokeSolutionKey Decision
1 State Chaos — task failed silently, status stayed "pending", manual triage daily State Machine — LOADED→RUNNING→REVIEW→DONE enforced in 91 lines Dict, not DB. Explicit beats implicit
2 Race Conditions — cron fired twice, parallel execution, Airtable corrupted Idempotency Lock — claim/release/lease-expiry/sweep via Airtable fields Zero new infra. Airtable is the distributed lock store
3 LLM Trust — LLM claimed "done" but code unwritten, research had no evidence LENS Gate — mechanical check: run_id + log_summary + writeback_ts must exist LLMs should not validate LLMs. Lesson from CER Evals
4 Memory Loss — pipeline step 3 had no idea what step 1 did TaskContext — append output to Airtable messages[], inject into prompt Raw text, not vector DB. Simple, debuggable
5 Human Disconnect — tasks ran for hours, no visibility or phone control Checkpoint System — review/decision/blocked/notify, WeChat↔Dashboard Feishu push + Airtable state + WeChat interaction
The correct build order

Week 1: n8n cron + Airtable queue + single LLM call. Manual verify. Week 2: State machine + LENS gate. Week 3: Lock + TaskContext. Week 4: Checkpoint + multi-agent. Don't build the full stack first. Each layer exists because the previous layer's pain became real.

09 · Takeaways

3 件可以试试的事 + 1 条记住就行的法则

  1. 明天：写下这周你最重复的 3 个任务。每个问一句：跑之前能画出完整流程图吗？能 → 用 Dify/n8n 搭一个。每个 30 分钟。
  2. 下周：挑一个做得最好的任务，写一个 SKILL.md。把你的标准、反模式、输出格式编码进去。粘贴到 Copilot Chat。看质量跳升。
  3. 本月：自动化任务超过 5 个时，加一个状态机。显式转换（pending→running→done），一个 dict 就够了。50 行代码省掉每天早晨的手工排查。
黄金法则

确定性是最好的路由器。在伸手拿 LLM 之前先问：这条路能不能提前画出来？能 → 用管道。不能 → 用 agent。需要专家品位 → 用 skill。做得最少的那个工具，往往就是最合适的。

09 · Takeaways

3 Things to Try + 1 Rule to Remember

  1. Tomorrow: Write down your 3 most repeated tasks this week. For each, ask: can I draw the flowchart before running it? If yes → build it in Dify/n8n. 30 minutes each.
  2. Next week: Pick your best task and write a SKILL.md. Encode your standards, anti-patterns, and output format. Paste it into Copilot Chat. Watch the quality jump.
  3. This month: When you have >5 automated tasks, add a state machine. Explicit transitions (pending→running→done) in a single dict. 50 lines of code that saves hours of manual triage.
The golden rule

Determinism is the best router. Before you reach for an LLM, ask: is this path pre-drawable? If yes, use a pipeline. If no, use an agent. If you need expert taste, use a skill. The tool that does the least is often the right one.
