01 · Framework

Three Paths to Automation

Not one tool, not one approach. Three distinct paths — each with its own strengths, boundaries, and sweet spots.

Path 1
n8n / Dify
Deterministic workflow engines. Visual programming with nodes. Event triggers + fixed execution paths. Flowchart drawn once, runs forever.
cron taskswebhooksdata sync
Path 2
Skill + MCP
Crystallized domain expertise as reusable context + tool protocol. Every invocation hits "expert mode." MCP standardizes how tools connect.
SKILL.mdMCP serverssingle-shot quality
Path 3
Agent Architecture
Runtime decision engines. Each step depends on the previous result. Built with LangGraph, CrewAI, or custom frameworks. The map is drawn as you walk.
LangGraphCrewAIcustom harness
The key distinction

Path 1 = pre-drawn map. Path 2 = expert snapshot. Path 3 = drawn while walking. Choose based on determinism, not complexity.

02 · Comparison

Capability Boundaries

Each path has a clear frontier where it stops being useful.

Path 1 · n8n / Dify

Strengths

  • Visual debugging — see exactly what ran
  • 400+ native integrations (APIs, DBs, AI)
  • Zero-code cron + webhook triggers
  • Self-hosted = full data control

Limits

  • Complex logic → spaghetti flowcharts
  • No runtime decision-making
  • High-aesthetic output requires external tools
  • Visual programming doesn't scale past ~50 nodes

Path 2 · Skill + MCP

Strengths

  • Expert-quality output every time
  • Knowledge accumulates (skills evolve)
  • MCP standardizes tool interfaces
  • Near-zero marginal cost per invocation

Limits

  • Requires upfront authoring investment
  • No runtime adaptability — fixed expertise
  • MCP ecosystem still maturing (auth, discovery)
  • Single-shot only — no multi-step planning

Path 3 · Agent Architecture

Strengths

  • Handles open-ended, multi-turn tasks
  • Dynamic tool selection at runtime
  • Can self-correct and retry
  • Orchestrates Path 1 + Path 2 as tools

Limits

  • Highest cost per task (multi-LLM-call)
  • Unpredictable — same input, different paths
  • Requires observability infrastructure
  • Overkill for deterministic workflows

04 · Decision Guide

When to Use What

Match the scenario to the path. Don't force one tool to do everything.

ScenarioBest PathWhy
"Every morning, scrape 3 sources and send a digest"n8nFixed schedule, fixed process. Zero decisions needed.
"Build a presentation with consistent branding"SkillSingle-shot, high-aesthetic. Expertise is crystallized.
"Research a topic and write a deep article"Agent + SkillRuntime research decisions + structured writing skill.
"Video pipeline: idea → script → generate → publish"n8n + Agent + SkillAll 3: n8n captures, Agent evaluates, Skill generates.
"Sync data between Airtable, Feishu, and Discord"n8nPure state sync. Deterministic. No AI needed.

08 · Practice

How I Built It

Step-by-step. What I actually did, in what order, with what tools.

  1. Step 1: Install n8n (self-hosted via npm). Build a single workflow: cron trigger → HTTP request to GitHub API → write to Airtable. This teaches "pipeline thinking." ~1 hour.
  2. Step 2: Write your first SKILL.md. Pick your most frequent task. Encode the best practices, common pitfalls, and output format into a markdown file. Place it in the skills directory. ~2 hours.
  3. Step 3: Connect a tool via MCP. Start simple: filesystem MCP server. Then Airtable MCP. This teaches the tool protocol pattern. ~1 hour.
  4. Step 4: Build a minimal agent harness. State machine, lock manager, LENS validator. Or use LangGraph if you prefer a framework. Wire it to call your n8n webhooks and your skills. ~4 hours.
  5. Step 5: Add observability. Structured logging with task_id. Feishu thread notifications per task. Airtable as the state ledger. Now you can see what's happening. ~2 hours.
Key lesson

Each step delivers standalone value before the next begins. Don't build the full architecture first — build the first layer, get value, then add the next.

09 · Takeaways

What I Learned

  1. Determinism is the best router. Don't ask "which tool is best?" Ask "is this sub-task deterministic?" The answer routes to the right path.
  2. Skills compound. Workflows don't. A workflow is a fixed path. A skill is accumulated expertise. Invest in skills.
  3. Observability before intelligence. Before making agents smarter, make their actions visible. Feishu threads + Airtable state = free observability.
  4. Start ugly, then refactor. My first harness was 3 scripts. The 20-commit refactor came after I knew what patterns mattered. Don't design in a vacuum.
  5. LLMs should not validate LLMs. Mechanical LENS gates catch 100% of evidence-pack failures. Zero hallucinations in validation.
