01 · Context

The Three Waves → Three Paths

过去半年，AI 自动化经历了三次范式迭代。每次解决前一个问题，同时暴露新瓶颈。现在的答案是：按确定性分层。

WaveApproachSolvedNew Problem
1All-in LLM chatNL as universal interfaceEvery task = new conversation
2All-in n8n/DifyRepeatable workflowsComplex logic → spaghetti
3 (now)Layered by determinismRight tool per sub-taskRequires upfront design

Path 1 · n8n / Dify

Deterministic pipelines. Fixed path, runs forever. cron, webhooks, data sync.

Path 2 · Skill + MCP

Crystallized expertise as context. Every call = expert mode. Single-shot quality.

Path 3 · Agent

Runtime decision engine. Map drawn as you walk. LangGraph, CrewAI, custom harness.
Core insight

"Which tool is best?" is wrong. "How deterministic is this sub-task?" — that routes to the right path.

02 · Boundaries

Capability Boundaries

Each path has a clear frontier where it stops being useful. Know when to switch.

Path 1 · n8n/Dify

Strengths
  • Visual debugging
  • 400+ integrations
  • Zero-code triggers
  • Self-hosted
Limits
  • Spaghetti at scale
  • No runtime decisions
  • No high-aesthetic output
  • ~50 node ceiling

Path 2 · Skill+MCP

Strengths
  • Expert quality every time
  • Knowledge accumulates
  • Near-zero marginal cost
  • MCP standardizes tools
Limits
  • Upfront authoring cost
  • No runtime adaptability
  • MCP ecosystem maturing
  • Single-shot only

Path 3 · Agent

Strengths
  • Open-ended tasks
  • Dynamic tool selection
  • Self-correct & retry
  • Orchestrates P1+P2
Limits
  • Highest cost
  • Unpredictable paths
  • Needs observability
  • Overkill for fixed paths
When MCP isn't needed yet

LLM platforms now natively handle filesystem, fetch, DB, GitHub. MCP adds a hop. Skip it until you have cross-platform needs.

How I Built It

Each workflow = a JSON file I wrote → imported into n8n. Triggers + data sources are fixed. The middle nodes (message format, filter rules, tag logic) are editable in the n8n UI — no code needed. This is Vibe Design: Agent designs the skeleton, human tweaks the middle.

07 · Tutorial

How I Built It — 5 Steps

  1. Install n8n (self-hosted via npm).Build one workflow: cron → GitHub API → Airtable. ~1 hour. Teaches pipeline thinking.
  2. Write your first SKILL.md.Your most frequent task. Encode best practices, pitfalls, output format. ~2 hours. First crystallized expertise.
  3. Connect a tool (MCP or native).Filesystem or Airtable. Teaches the tool protocol pattern. ~1 hour.
  4. Build a minimal agent harness.State machine + lock manager + LENS validator. Or use LangGraph. Wire to n8n + skills. ~4 hours.
  5. Add observability.Structured logging with task_id. Feishu thread notifications. Airtable state ledger. Dashboard sync. ~2 hours.
Key lesson

Each step delivers standalone value. Don't build the full stack first — build layer 1, get value, add next.

09 · Takeaways

What I Learned

  1. Determinism is the best router.Is this sub-task deterministic? → routes to the right path.
  2. Skills compound. Workflows don't.Fixed path vs accumulated expertise. Invest in skills.
  3. Observability before intelligence.Feishu threads + Airtable state = free observability.
  4. Start ugly, refactor later.20-commit refactor came after knowing what patterns matter.
  5. LLMs should not validate LLMs.LENS gate catches 100% of evidence failures. Zero hallucination.
