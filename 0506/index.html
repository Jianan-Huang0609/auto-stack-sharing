03 · The Secret

Three Paths, Not One Tool

The key insight: sort tasks by determinism. Different problems need different engines.

Path 1 · n8n / Dify

Fixed path, runs forever. Deterministic: cron, webhooks, data sync.

Path 2 · Skill

Expert context injection. Single-shot, high-quality output with encoded best practices.

Path 3 · Agent / CLI

Runtime decisions. Multi-step reasoning. "Figure it out as you go."
QuestionAnswer→
Can you draw the flowchart before running?Yesn8n/Dify
Single-shot, high-quality output?YesSkill
Needs runtime decisions?YesAgent
The rule

If you can draw the flowchart → n8n. If you need expert taste → Skill. If you need to figure it out step by step → Agent.

07 · On-Ramp B

Your company is deploying Dify. Here's the exact pattern that makes it useful — not just another chatbot.

Pattern 1 · Cron + API

Schedule → HTTP fetch → filter → notify. The hello-world of automation. 30 minutes to build, runs forever.

Pattern 2 · Multi-System Sync

08 · On-Ramp C

MAE — 5 Engineering Challenges I Had to Solve

The gap between "a script that calls an LLM" and "an agent system that runs itself for days."

#What BrokeSolutionKey Decision
1 State Chaos — task failed silently, status stayed "pending", manual triage every morning State Machine — LOADED→RUNNING→REVIEW→DONE enforced in 91 lines Dict, not DB. Explicit transitions beat implicit conventions
2 Race Conditions — cron fired twice, same task ran in parallel, Airtable corrupted Idempotency Lock — claim/release/lease-expiry/sweep via Airtable fields Zero new infrastructure. Airtable is the distributed lock store
3 LLM Trust — LLM said "done" but code wasn't written, research had no evidence LENS Gate — mechanical check: run_id + log_summary + writeback_ts must exist LLMs should not validate LLMs. Lesson from CER Evals
4 Memory Loss — pipeline step 3 had no idea what step 1 did. Each call was amnesic TaskContext — append every output to Airtable messages[], inject into prompt Raw text append, not vector DB. Simple, debuggable, effective
5 Human Disconnect — tasks ran for hours. No visibility, no way to intervene from phone Checkpoint System — review/decision/blocked/notify nodes, WeChat→Dashboard control Feishu push + Airtable state + WeChat compact interaction
The correct build order

Week 1: n8n cron + Airtable queue + single LLM call. Manual verification. Week 2: State machine + LENS gate. Week 3: Lock + TaskContext. Week 4: Checkpoint + multi-agent. Don't build the full stack first. Each layer exists because the previous layer's pain became real.

09 · Takeaways

3 Things to Try + 1 Rule to Remember

  1. Tomorrow: Write down your 3 most repeated tasks this week. For each, ask: can I draw the flowchart before running it? If yes → build it in Dify/n8n. 30 minutes each.
  2. Next week: Pick your best task and write a SKILL.md. Encode your standards, anti-patterns, and output format. Paste it into Copilot Chat. Watch the quality jump.
  3. This month: When you have >5 automated tasks, add a state machine. Explicit transitions (pending→running→done) in a single dict. It's 50 lines of code that saves hours of manual triage.
The golden rule

Determinism is the best router. Before you reach for an LLM, ask: is this path pre-drawable? If yes, use a pipeline. If no, use an agent. If you need expert taste, use a skill. The tool that does the least is often the right one.
