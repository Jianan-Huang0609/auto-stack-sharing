METHOD22

n8n 怎么开始？

先做最小闭环，不要一开始追求全自动。

我的设置

Airtable / n8n / Feishu / Dashboard

Airtable 做状态源；n8n 编排；Feishu/WeChat 通知；Dashboard 可视化。

适合做

提醒、同步、状态流转

固定规则判断、系统间连接、流程可观察。

踩坑

Credential / 命名 / 失败路径

权限最容易卡；workflow 多了会乱；没有失败路径就不知道坏了。

Tips

AI 写 JSON / Code 节点

让 AI 先写 workflow JSON；复杂判断放 Code 节点；每条 workflow 都要失败路径。

METHOD23

Skills：能力层

Skill 不是 prompt 收藏夹，而是可重复执行的做事方法。

Concept

场景 / 输入 / 步骤 / 输出 / 验收

Skill 把一次经验变成下一次可以稳定调用的 SOP。

Feynman

Prompt 是提醒，Skill 是 SOP

新人能照 SOP 做事，Agent 也能照 Skill 稳定产出。

真正的效率，是把做事方法沉淀下来。
METHOD24

Skill 怎么写才有用？

一个好的 Skill 必须有 anatomy。

我的设置

PLO / slides / video / writing

项目状态、HTML 课件、视频生产、知识沉淀、dashboard。

适合做

重复三次以上的任务

高审美交付、结构化分析、项目编排。

踩坑

只有原则，没有步骤

只写 prompt 不写验收；没有 examples，Agent 会脑补。

Tips

写清输入输出和反例

适用场景、步骤、输出格式、验收标准、反例都要写。

METHOD25

Agent OS：协作层

Agent OS 不是多开聊天窗口，而是目标、工具、记忆、执行循环、反馈和可视化的组合。

Concept

目标 + 工具 + 记忆 + 循环 + 可视化

把 AI 从一次性对话组织成持续推进任务的系统。

Feynman

从临时顾问到小团队

每个人有岗位、有任务账本、有交接记录、有复盘机制。

多 Agent 的核心不是多，而是组织方式。
METHOD26

Agent 怎么搭才不会乱？

从一主脑 + 一个专业 Agent 开始。

我的设置

SAM + Andrew/Rex/Lulu/Alex

主脑协调，专业 Agent 分工。

必备机制

SOUL / HEARTBEAT / memory / tasks

角色、节奏、长期状态、任务账本、Dashboard。

踩坑

角色不清 / 无任务账本

互相覆盖、丢上下文、没人信任它在工作。

Tips

升级规则 + 证据格式

每个长任务要有状态源、产物链接和 blocker。
