EVOLUTION08

为什么还在用 n8n？

Agent 框架管思考和协作，n8n 管触发和连接。两者不是替代关系，而是分工：n8n 做稳定的"神经系统"，Agent 做"大脑"。

🪝

Webhook 稳定触发

Agent 框架能发消息，但不具备"等外部信号再行动"的可靠机制。n8n 原生支持 Webhook、Cron、轮询三种触发。

适用：飞书消息 → 触发 AI → 回写结果，不靠人手动点火
⚡

AI Vibe 快速跑通

Code 节点直接调用 AI API：改 prompt 不需要重部署，改 workflow 比改代码快 10 倍。适合快速验证想法。

适用：AI 总结、分类、提取字段 → 嵌入 workflow，半小时跑通闭环
🔗

系统集成零成本

Airtable、飞书、微信、GitHub、Dashboard —— 一次配置，永久使用。不需要为每个系统写适配代码。

适用：任务状态跨系统同步、Dashboard 自动更新、通知路由分发
模型越来越强，但如果没有系统承接，它还是停在一次性回答。

METHOD19

n8n 怎么开始？

最小闭环比宏大自动化更重要。先让一个任务可流转、可观察、可确认，再扩展。

SETUP

我的设置

Airtable 做状态源；n8n 编排 workflow；Feishu/微信做通知；Dashboard 可视化；GitHub 保存 JSON。

适合做什么

提醒、同步、状态流转

固定规则判断、系统间数据连接、让流程可观察可审查。不适合需要复杂判断或主观决策的任务。

踩过的坑

Credential / 命名 / 失败路径

1.Credential 和权限最容易卡。2.workflow 超 10 个后命名混乱。3.没有失败路径，坏了没人知道。4.一开始就追求全自动。

TIPS

AI 写 JSON + Code 节点

1.让 AI 先写 workflow JSON 导入微调。2.复杂判断放 Code 节点。3.每条 workflow 必有失败路径。4.先 One Task One Workflow。

💡

不是先学 n8n，是先有一个具体痛点

先找到一个真实重复的痛点——比如"每天手动查逾期任务并通知"——再用 n8n 解决它。最小闭环比宏大自动化更重要。

起步原则：先让一个 task 走通完整闭环，再扩展。
METHOD20

Skills：能力层

Skill 不是 prompt 收藏夹，而是可重复执行的做事方法。

专业概念

Skill = 场景 + 输入 + 步骤 + 输出格式 + 验收标准

把重复三次以上的任务流程化，让 Agent 每次都能稳定产出。关键是 input/output contract。

费曼解释

从口头提醒到 SOP

Prompt 像一句口头提醒。Skill 像一份 SOP：先收集状态、再设计结构、再写正文、再对照验收标准检查。新人照 SOP 能做事，Agent 照 Skill 也能稳定产出。

真正拉开差距的，不是每次问得更聪明，而是把做事方法沉淀下来。
METHOD21

Skill 怎么写才有用？

好的 Skill 必须有 anatomy：场景、输入 contract、执行步骤、输出格式、验收标准、常见反例。

场景

什么时候 Skill 化

重复 3 次以上的任务、有明确输入输出的任务、需要审美和结构约束的任务。一次性的不用急着写。

Skill Anatomy

Skill 必须包含什么

适用场景、输入 Contract、执行步骤、输出格式、验收标准、常见反例——缺任何一个，Skill 就是"原则"不是"方法"。

踩过的坑

只写原则不写步骤

1.只有原则没有步骤。2.没有验收标准，Agent 自己脑补。3.没有反例。4.视觉类任务不能只看"生成没有"，要看审美和信息密度。

TIPS

闭卷跑一次验证

写好 Skill 后，假装自己是第一次看到这个 Skill 的 Agent，闭卷跑一次全流程，看输出是否对齐验收标准。不过关就改。

✗ 裸 Prompt 写的 PPT

模板化、信息密度低、没有视觉系统、像 AI 生成的套壳页面，不能直接用于演讲或外部展示。

✓ Skill 约束后生成的 PPT

结构清楚、信息密度高、视觉统一、有明确的 section 节奏、可直接用于 45min 分享。

Skill 不是写完就完，要自己跑一次验证。
METHOD22

Agent OS：协作层

Agent OS 不是多开聊天窗口，而是目标、工具、记忆、执行循环、反馈和可视化的组合。

专业概念

Agent = 角色 + 目标 + 工具 + 记忆 + 循环 + 反馈

一个 Agent 不只是换个 system prompt。它包括：持久记忆、定期心跳、任务账本、证据追踪、升级规则、Dashboard 反馈。

费曼解释

从临时顾问到小团队

普通 Chatbot 像临时顾问：每次问每次答，不记得上次说了什么。Agent OS 像一个小团队：有岗位、有任务账本、有交接记录、有复盘机制、有 manager 在协调。

多 Agent 的核心不是多，而是组织方式。
METHOD23

Agent 怎么搭才不会乱？

先定义角色边界和升级规则，再建任务账本，再配可视化。不要一上来就建五个 Agent。

SETUP

SAM 主脑 + 4 专业 Agent

SAM 全局协调和记忆管理；Andrew 学习研究；Rex 工作项目；Lulu 内容写作；Alex 个人节奏。共享 memory 和 tasks。

必备机制

七文件机制

SOUL 定义角色；USER 存偏好；AGENTS 定协议；HEARTBEAT 定节奏；memory 存决策；tasks 管当前；Project State 管长线。

踩过的坑

太多 / 无账本 / Heartbeat空转

1.Agent 太多增加协调成本。2.没账本，多 Agent 变混乱。3.Heartbeat 只检查不推进。4.没有 Dashboard，人无法判断是否真的在推进。

TIPS

Agent 让学习变简单，但人脑不可省略

AI 可以帮你搜索、整合、输出、分析。但当你不知道一个信息时，它对你来说就像不存在。

AI 可以自动化

搜索/整合/输出/分析

学习一个 topic，Agent 帮你搜资料、做摘要、输出框架、对比表。信息链路变得非常短。

人脑不可省略

判断/选择/品味/方向

哪些问题重要？哪些方向值得投入？什么品味是对的？AI 提供素材，但不能替你形成判断。

搜索、整理、输出可以自动化；兴趣、判断、内化不能省略。

SELF-EVOLUTION · 自进化配置

系统如何自己变好

不是写好 Skill 就结束了。每次执行后记录反馈 → 对比验收标准 → 自动 dry-run → human confirm → 更新 Skill。Skill 不是文档，是活的。

Human Confirm人看过 dry-run 结果后确认锁版，避免自进化失控
4
更新 Skill + 回写确认后的改进写入 Skill.md → GitHub → Dashboard 标记已迭代
