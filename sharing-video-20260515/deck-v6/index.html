METHOD21

n8n：流程层

Workflow automation 本质：触发、读取状态、判断、执行、反馈。

专业概念

Trigger → State → Logic → Action

Trigger 决定何时启动。Data/State 读取当前任务状态。Logic 判断下一步。Action 把结果推送到 Feishu、Dashboard 或微信。

费曼解释

办公室自动化调度员

n8n 像一个调度员：看到任务逾期，去表格查状态，判断要不要提醒，需要就发消息，更新看板。不是万能大脑，但能让信息按规则流动。

n8n 让 AI 输出进入真实管理系统，不再停在聊天框。
METHOD22

n8n 怎么开始？

最小闭环比宏大自动化更重要。先让一个任务可流转、可观察、可确认，再扩展。

我的设置

Airtable / n8n / Feishu / Dashboard / GitHub

Airtable 做状态源；n8n 编排 workflow；Feishu/微信做通知；Dashboard 可视化；GitHub 保存 JSON。

适合做什么

提醒、同步、状态流转

固定规则判断、系统间数据连接、让流程可观察可审查。不适合需要复杂判断或主观决策的任务。

踩过的坑

Credential / 命名 / 失败路径

1.Credential 和权限最容易卡。2.workflow 超过 10 个后命名混乱。3.没有失败路径，坏了没人知道。4.一开始就追求全自动。

我的 Tips

AI 写 JSON + Code 节点

1.让 AI 先写 workflow JSON，导入微调。2.复杂判断放 Code 节点。3.每条 workflow 必有失败路径。4.先从 One Task One Workflow 开始。

起步原则：先让一个 task 走通完整闭环，再扩展。
METHOD23

Skills：能力层

Skill 不是 prompt 收藏夹，而是可重复执行的做事方法。

专业概念

Skill = 场景 + 输入 + 步骤 + 输出格式 + 验收标准

把重复三次以上的任务流程化，让 Agent 每次都能稳定产出。关键是 input/output contract。

费曼解释

从口头提醒到 SOP

Prompt 像一句口头提醒。Skill 像一份 SOP：先收集状态、再设计结构、再写正文、再对照验收标准检查。新人照 SOP 能做事，Agent 照 Skill 也能稳定产出。

真正拉开差距的，不是每次问得更聪明，而是把做事方法沉淀下来。
METHOD24

Skill 怎么写才有用？

好的 Skill 必须有 anatomy：场景、输入 contract、执行步骤、输出格式、验收标准、常见反例。

我的 Skill 体系

PLO / Slides / Video / Writing / Dashboard

product-lifecycle-orchestrator 管项目状态；frontend-slides 管 HTML Deck；ai-video-production 管视频；writing-book 管长文；airtable-dashboard 管可视化。

适合 Skill 化的任务

重复 3 次以上 + 明确输入输出

高审美交付（PPT/HTML/视频）、结构化分析、项目编排、信息整理。不适合一次性的、创意发散任务。

踩过的坑

只写原则不写步骤

1.只有原则没有步骤。2.只有 prompt 没有验收标准。3.没有 input/output contract，Agent 自己脑补。4.没有反例。5.视觉类任务不能只看"生成了没有"，要看审美、信息密度、可讲性。

Skill.md 模板

场景/输入/步骤/输出/验收/反例

1.明确适用场景。2.写清输入格式。3.步骤具体到可执行。4.定义验收标准。5.给出至少 2 个反例。写好 Skill 后自己闭卷跑一次验证。

Skill 不是写完就完，要自己跑一次验证。
METHOD25

Agent OS：协作层

Agent OS 不是多开聊天窗口，而是目标、工具、记忆、执行循环、反馈和可视化的组合。

专业概念

Agent = 角色 + 目标 + 工具 + 记忆 + 循环 + 反馈

一个 Agent 不只是换个 system prompt。它包括：持久记忆、定期心跳、任务账本、证据追踪、升级规则、Dashboard 反馈。

费曼解释

从临时顾问到小团队

普通 Chatbot 像临时顾问：每次问每次答，不记得上次说了什么。Agent OS 像一个小团队：有岗位、有任务账本、有交接记录、有复盘机制、有 manager 在协调。

多 Agent 的核心不是多，而是组织方式。
METHOD26

Agent 怎么搭才不会乱？

先定义角色边界和升级规则，再建任务账本，再配可视化。不要一上来就建五个 Agent。

我的设置

SAM 主脑 + 4 专业 Agent

SAM 全局协调和记忆管理；Andrew 学习研究；Rex 工作项目；Lulu 内容写作；Alex 个人节奏。共享 memory 和 tasks。

必备机制

SOUL + USER + AGENTS + HEARTBEAT + memory + tasks

SOUL 定义角色；USER 存偏好；AGENTS 定工作协议；HEARTBEAT 定检查节奏；memory 存长期决策；agent_tasks 管当前任务；Dashboard 是信任层。

踩过的坑

太多 / 无账本 / Heartbeat 空转

1.Agent 太多增加协调成本，先从最小系统开始。2.没任务账本，多 Agent 变成多窗口混乱。3.Heartbeat 只检查不推进，没有价值。4.没有 Project State，长对话会反复问已回答的问题。5.没有 Dashboard，人无法判断系统是否真的在推进。

起步 Tips

一主脑 + 一专业 Agent

1.先搭一主脑一专业 Agent，不要一上来搭十几个。2.每个 Agent 要有边界和升级规则。3.长项目必须维护 Project State。4.Dashboard 是信任层，不是装饰。5.多 AI API 的价值在路由，不在数量。

先做最小 Agent OS：任务进入，AI 推进，Dashboard 可见，人确认。

LEARNING29

Agent 让学习变简单，但人脑不可省略

AI 可以帮你搜索、整合、输出、分析。但当你不知道一个信息时，它对你来说就像不存在。

AI 可以自动化

搜索/整合/输出/分析

学习一个 topic，Agent 帮你搜资料、做摘要、输出框架、对比表。信息链路变得非常短。

人脑不可省略

判断/选择/品味/方向

哪些问题重要？哪些方向值得投入？什么品味是对的？AI 提供素材，但不能替你形成判断。

搜索、整理、输出可以自动化；兴趣、判断、内化不能省略。
