# Deck V6 · 需求模式提取 · Skill 进化素材

## 核心设计原则（从你的反馈中提取）

### 1. 幻灯片 ≠ 讲稿
- HTML 页不应该是文字版讲稿
- 页面放：视觉证据、结构引导、关键数字、金句锚点
- 你嘴上说的 ≠ 屏幕上放的

### 2. 信息密度判断标准
- 正文词数 < 30 → 太薄，需要视觉物
- Section Break 页必须有视觉引导（图/流程），不能只有标题
- 方法页需要：概念 + 费曼 + 设置 + 踩坑 + Tips（五要素质检）

### 3. 素材引用规则
- 每张图只能在一页当主角，禁止同一张图在多页重复
- assets 里有素材一定要用，不能放着不用
- 真实截图 > 模拟对话 > 占位文字

### 4. 排布偏好
- 重要性高 → 大图 + 小说明
- tab 切换机制优于三栏均分
- 左列表右详情优于纯文字卡
- 进度链/时间线视觉优于纯文字叙述

### 5. 叙事节奏要求
- 每段肌肉展示：总览视觉 → 单项深挖 → 过渡
- 删除重复铺垫页
- 开头提问 → 结尾 callback
- 不要"概念教学"页（如纯费曼解释、纯演进历史）

## 可复用操作模式

### 改一页的标准流程
1. 先看当前页标题+subtitle+key句+正文词数
2. 对照讲稿找到对应段落
3. 判断这页是"证据页""流程页""方法页"还是"过渡页"
4. 选模板：tab切换 / 左右分栏 / 三卡 / 时间线 / pipeline / 星形图
5. 从 assets 选素材，避免重复
6. 写 CSS + HTML，渲染截图验证
7. git commit + push

### 批量改页面流程
1. 先逐页诊断（词数+素材+排布）
2. 排优先级（🔴空白页 > 🟡素材重复 > 🟢微调）
3. 一个 Python 脚本改多页
4. 批量 headless 截图
5. 一次 commit

### 容易犯的错
- 讲稿文字灌进 HTML ← 已经被你纠正
- 同一素材多页复用 ← 已经被你纠正
- 没确认就删页面 ← 已经被你纠正
- 改完没重新渲染验证 ← 应该每次都做的

## Skill 进化方向

### frontend-slides Skill 应加入的约束
1. 页面正文词数下限检查（方法页 > 40，证据页 > 20）
2. 素材去重检查（同一图片只能在一页出现）
3. 每页必须有"这一页讲什么、放什么证据、观众看到什么"三要素
4. 禁止纯文字页（除非封面/结尾）
5. Section Break 必须有视觉物
6. 优先使用 tab 切换 > 三栏均分
7. 结尾页必须 callback 开头问题
